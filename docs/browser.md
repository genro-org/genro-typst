# Python and JavaScript playground

The playground uses the Python or JavaScript Genro Typst builder to create a
document and shows three views together:

1. Editable Python and JavaScript recipe tabs in CodeMirror 6, with syntax
   highlighting, line numbers and search.
2. The ordinary Typst source generated by `builder.render()`.
3. The SVG document compiled and rendered by Typst through WebAssembly.

**The typesetting is Typst's work.** Thanks to Laurenz Mädje, Martin Haug,
the Typst team and all contributors. Browser compilation and rendering use
[Myriad-Dreamin's typst.ts](https://github.com/Myriad-Dreamin/typst.ts).
Genro supplies the authoring layer and this example UI; it is an independent
project. See [acknowledgements](acknowledgements.md).

## Start the example

From the repository root, with Node.js 22 or later and Python 3.10 or later:

```bash
python3 -m venv venv
venv/bin/python -m pip install -e .
npm ci --prefix js
npm run demo --prefix js
```

Open [http://127.0.0.1:8172/](http://127.0.0.1:8172/). To choose another port:

```bash
PORT=8173 npm run demo --prefix js
```

The Node server binds only to `127.0.0.1`, serves the page and runs Python
recipes locally. It uses `venv/bin/python` from this checkout when available,
otherwise `python3`. Choose a different interpreter, with Genro Typst installed,
using `GENRO_TYPST_PYTHON=/path/to/python npm run demo --prefix js`.
Kajenn, the separate PDF Builder application, the Python compiler extra and
the official Typst CLI are not required for this preview. Stop the server
with Ctrl+C.

The first build needs network access to install npm dependencies and download
four Libertinus Serif fonts, New Computer Modern Math and their license notices from the official
`typst-assets` repository, pinned to `v0.13.1`. Subsequent builds reuse these
font files. The browser loads the builder, compiler, renderer and fonts from
the local server: the supplied example does not upload documents or require
a CDN at runtime.

## Browse the element collection

The sidebar contains **149 element recipes plus the introductory document**:
129 native Typst elements, 12 language constructs, and 8 Genro document/data
elements. This is the complete element catalog supported by this builder,
not an inventory of every function in the Typst standard library.
Search by name or description, or select a category such as Mathematics,
Page layout or Graphics and images. Selecting an example loads its editable
Python and JavaScript recipes, generated Typst source and SVG preview.

Edits are kept separately for each example and language **during the current
page session**; switching tabs or examples does not discard them. Reloading
the page does. **Reset Python** or **Reset JavaScript** restores only the
active language. Images, bibliographies,
imports and includes come with their required files: expand **Included file**
to inspect or download one. These files are loaded into the compiler's virtual
filesystem and cleared when compiling a different example. When compiling a
downloaded `.typ` outside the browser, download its included files alongside it.

**Check all Python examples** or **Check all JavaScript examples** compiles
the original recipes of the active language sequentially, reports
successes and diagnostics, and then restores your selected recipe and preview.
It does not overwrite your drafts. With the pinned typst.ts **0.7.0** runtime,
**149 of the 150 documents render to SVG**. The remaining example, **divider**,
uses an element unavailable in that browser compiler; it is marked in the list
and explained above the editor. Its generated source is valid with the
reference Python Typst **0.15.0** compiler. No substitute element is inserted.

## Python and JavaScript tabs

Each of the 150 examples, including the introductory document, has **Python**
and **JavaScript** tabs above one shared Typst source panel and SVG preview.
Switch tabs with a click or the arrow keys. Selecting a tab runs that language's
recipe and updates the shared preview. The chosen language stays selected
when you browse another example.

Both recipes are editable. **Live preview**, **Run Python** / **Run JavaScript**,
and Ctrl+Enter / Command+Enter operate on the active tab. The original Python
and JavaScript recipes produce identical Typst source, verified by executing
both in tests. Edits are independent: changing Python does not rewrite
JavaScript, and changing JavaScript does not rewrite Python. The note above
the editor identifies which language currently drives the preview.

Python runs in a fresh local process using the installed Genro Typst package.
The server loads the recipe's builder class and calls `create()` and `render()`,
using the same class selection as the CLI: one locally defined builder class,
or an explicit `BUILDER` when there are several. The `if __name__ == "__main__"`
block is not executed. Included files are available in a temporary working
directory. The resulting Typst source is sent back to the browser, where the
same Typst WebAssembly compiler produces SVG for both languages.

**Download .typ.py** saves the current Python recipe, including your edits.
The supplied recipes include a `Document.run()` entry point. With Genro Typst installed, run it locally:

```bash
python heading.typ.py
python heading.typ.py --svg
```

Download any included files alongside the recipe. SVG/PDF compilation requires
the Python compiler extra (`pip install '.[pdf]'` from this checkout).

## Edit, run and download

With **Live preview** enabled, edits update Typst and SVG after a short pause.
Disable it to run manually with **Run Python** / **Run JavaScript** or
Ctrl+Enter / Command+Enter.

In JavaScript, define a `TypstBuilder` instance named `builder`; the example
renders it after executing the recipe. `TypstBuilder`, `expr`, `length`,
`color`, `label`, `markup` and `Bag` are provided to the recipe. The generated
Typst source also uses CodeMirror, in read-only mode.

```javascript
const builder = new TypstBuilder();
const doc = builder.root.document({ paper: 'a5' });
doc.set_rule({ target: 'text', font: 'Libertinus Serif' });
doc.heading('Hello from JavaScript', { level: 1 });
doc.par('Typeset in the browser by Typst.');
doc.v({ content: length('5mm') });
```

Use `content` for structured values such as `length(...)`; a lone object
argument is interpreted as an attribute object by the fluent API.

In Python, define a builder subclass with a `main(root)` method, called by
the builder's `create()` lifecycle, for example:

```python
from genro_typst import TypstBuilder


class Document(TypstBuilder):
    def main(self, root):
        doc = root.document(paper="a5")
        doc.heading("Hello from Python", level=1)
        for item in ["First", "Second", "Third"]:
            doc.par(item)


if __name__ == "__main__":
    Document.run()
```

**Download .typ** saves the generated source. **Download .svg** saves a
standalone SVG of the rendered document. Multipage documents are combined
vertically in a single SVG by typst.ts. Python, JavaScript and Typst errors appear
in the preview panel; failed runs clear the old preview so it cannot be
mistaken for the current result. Reset restores and runs the active language's
original recipe. Responses from an earlier edit or tab are discarded.

This is a local developer playground for trusted recipes. JavaScript executes
in the page with normal browser permissions; Python executes on your machine
with your user permissions. A fresh process and temporary directory separate
runs, but are **not a security sandbox**. Do not expose this server publicly or
execute untrusted recipes. Python requests require the local page's origin and
session token; each worker has a 15-second execution limit and a 1 MiB output
limit. The generated SVG is displayed as an image, separate from the application
DOM.

## Files and static deployment

| File | Purpose |
|---|---|
| `js/examples/browser/index.html` | Page structure and credits |
| `js/examples/browser/style.css` | Responsive three-panel layout |
| `js/examples/browser/recipe.js` | Builder import, initial recipe and recipe execution |
| `js/examples/browser/catalog.json` | Paired recipes, reference Typst source and assets |
| `js/examples/browser/welcome.typ.py` | Executable Python version of the introductory example |
| `js/examples/browser/collection.js` | Search, categories, compatibility notes and session drafts |
| `js/examples/browser/editor.js` | CodeMirror setup for JavaScript, Python and read-only Typst |
| `js/examples/browser/compiler.js` | Local WASM compiler, fonts and isolated virtual files |
| `js/examples/browser/python.js` | Local Python execution client |
| `src/genro_typst/playground_worker.py` | Python recipe lifecycle and temporary assets |
| `js/examples/browser/main.js` | UI, local compiler loading and SVG delivery |
| `js/scripts/build-browser.mjs` | Bundle the builder and copy compiler/fonts/notices |
| `js/scripts/serve-browser.mjs` | Local page server and Python execution API |

Build separately with `npm run build:browser --prefix js`. Serve the contents
of `js/dist/browser/` over HTTP; opening `index.html` via `file://` is not
supported. Keep `vendor/`, `fonts/` and the third-party notices with the page.
Static hosting supports JavaScript previews. Python previews require the local
server above and an installed Python package; the page explains this if the
execution API is unavailable.
Generated output is ignored by Git and is not included in the library's npm
package.

The demo pins `@myriaddreamin/typst-all-in-one.ts` **0.7.0** and esbuild
**0.28.2** as development dependencies. The all-in-one module is approximately
37 MiB before HTTP compression, so initial loading is heavier than later
renders. This favors a self-contained example over an optimized production
bundle. Font files retain their upstream licenses; the built page links to
the bundled notices.

The browser compiler has its own release cycle, separate from the Python
binding pinned in this repository. The compatibility result above applies to
the supplied recipes and pinned runtime, not arbitrary edits. Additional font
families, custom assets or Typst packages require explicit integration.

## Maintain and verify the collection

Recipes are generated from the same executable catalog as the Python app,
including its nested contexts and supporting files. Regenerate from the
repository root with the Python development dependencies installed:

```bash
python tools/export_browser_examples.py
python tools/export_browser_examples.py --check
npm test --prefix js
npm run test:browser-server --prefix js
```

The export records each Python-generated Typst source. JavaScript tests execute
all 149 element recipes plus the introductory document and compare their
JavaScript output byte for byte with that reference. Python tests execute the
150 displayed Python recipes and verify the same source, as well as direct
execution of a downloaded recipe. They also check catalog coverage, search, draft preservation and
included files. Server integration tests exercise real Python execution,
request authorization, errors, timeouts and isolation between runs. CI checks
that the export is current and builds the playground. Use the active language's
**Check all** button for actual compilation in the browser.
Python and JavaScript recipes use the same method names, selected by a shared
alias table. Only `columns`, `move` and `label` require qualified calls in the
examples; the other methods keep their short grammar names.
CodeMirror is distributed under the MIT license; its notice is included with
the Typst, typst.ts and font acknowledgements in the built page.
